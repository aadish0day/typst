### 1.2.1 Core Engineering & Research Objectives Overview

The overarching aim of the **FactStamp** research and engineering project is to architect, implement, benchmark, and deploy a robust, zero-cost, privacy-preserving, and community-governed misinformation defense platform specifically optimized for the dynamics of the WhatsApp ecosystem in India. 

To bridge the critical gap between hyper-fast dark-social rumor propagation and the sluggish turnaround of centralized fact-checking newsrooms, the system is designed around **eight quantifiable, formal engineering and algorithmic objectives**:

```text
+--------------------------------------------------------------------------------------------------+
|                             FACTSTAMP SYSTEM OBJECTIVES MATRIX                                   |
+----+----------------------------------------------+----------------------------------------------+
| #  | Objective Title                              | Primary Technical Deliverable / Metric       |
+----+----------------------------------------------+----------------------------------------------+
| 1  | Frictionless Multimodal Claim Ingestion      | Dual text/image inputs; zero-auth onboarding |
| 2  | In-Browser WebAssembly OCR Text Extraction   | Client Tesseract.js pipeline; $0 cloud cost  |
| 3  | Token-Level Jaccard Duplicate Suppression    | J(A, B) >= 0.75; sub-100ms lookup latency    |
| 4  | Democratic 3-Verifier Quorum Queue           | N >= 3 independent reviews; primary URLs     |
| 5  | Multi-Factor Weighted Consensus Engine       | C = 0.40A + 0.30R + 0.30S confidence score   |
| 6  | Tamper-Resistant Anti-Sybil Defense Subsystem| Dynamic [0, 100] score; Firestore rule locks|
| 7  | WhatsApp-Native 1080x1080px Card Generator   | SVG <foreignObject> rasterization; OKLCH     |
| 8  | Public Analytical Misinformation Surveillance| 7-day rolling Recharts trends & leaderboards |
+----+----------------------------------------------+----------------------------------------------+
```

### 1.2.2 Detailed Elaboration of Engineering Objectives

#### Objective 1: Frictionless Multimodal Claim Ingestion Pipeline
- **Architectural Scope:** Construct a lightweight, highly responsive client intake interface permitting users to submit suspicious WhatsApp forwards across two distinct modalities:
  1. *Plaintext Submissions:* Support unstructured forward copy up to **2,000 characters** with automated whitespace normalization and stripping of forwarding headers (e.g., `[12:30 PM, 14/08/2026] +91...: Forwarded as received`).
  2. *Screenshot Submissions:* Provide an intuitive drag-and-drop and camera-roll file-picker accommodating standard image formats (JPEG, PNG, WebP) up to **5.0 megabytes**.
- **Interaction Constraint:** Implement an unauthenticated submission pipeline allowing first-time or casual users to submit suspicious claims instantaneously with **zero registration barriers**, preserving anonymity and eliminating user onboarding friction.
- **Client Compression Gate & Zero Cloud Storage Bill Model:** Implement an in-browser HTML5 Canvas compression pipeline that automatically downsamples incoming images to a maximum bounding box of $1200 \times 1200\text{px}$ and adjusts JPEG quality to compress raw image payloads into base64 data URIs under **500 kilobytes**, keeping storage entirely within Firestore document size limits and completely eliminating cloud storage bucket fees ($0.00 storage billing).

#### Objective 2: Automated In-Browser WebAssembly OCR Text Extraction
- **Architectural Scope:** Integrate a fully client-side Optical Character Recognition (OCR) pipeline directly within modern web browser runtimes using **Tesseract.js** compiled to WebAssembly (Wasm) and executed inside background Web Workers.
- **Privacy & Security Guarantee:** Ensure that raw image pixels are processed and transcribed locally within the user device's memory space, guaranteeing that private screenshots never transit unvetted across intermediate backend vision microservices.
- **Economic Feasibility:** Completely eliminate reliance on commercial computer vision cloud APIs (such as Google Cloud Vision API, AWS Textract, or Azure Cognitive Services), preserving an uncompromising **zero-dollar operational expenditure** baseline for the application's intake subsystem.

#### Objective 3: Real-Time Token-Level Duplicate Suppression Engine (Jaccard Similarity)
- **Algorithmic Scope:** Design and implement a high-throughput text normalization, punctuation elimination, stop-word filtering, and set-theoretic tokenization pipeline.
- **Mathematical Model:** Enforce the Jaccard similarity index:
  
  $$J(A, B) = \frac{|S_A \cap S_B|}{|S_A \cup S_B|} = \frac{|S_A \cap S_B|}{|S_A| + |S_B| - |S_A \cap S_B|}$$
  
  Where $S_A$ represents the token set of the incoming claim and $S_B$ represents the token set of an existing verified claim in the database.
- **Latency & Recall Benchmarks:** Enforce an empirical similarity threshold of **$J(A, B) \ge 0.75$** to detect duplicate forwards across Firestore collections in **under 100 milliseconds**, immediately redirecting the submitting user to existing certified fact-check verdicts and preventing queue congestion.

#### Objective 4: Democratic Community Quorum Verification Queue
- **Architectural Scope:** Construct an open, transparent public review registry powered by real-time Google Cloud Firestore v12.17.0 WebSocket snapshot listeners (`onSnapshot`), allowing authenticated community verifiers to inspect pending unverified forwards.
- **Quorum Gating Rule:** Enforce a strict minimum quorum requirement of **three ($N \ge 3$) independent, authenticated verifications** before a claim transitions from the `in_review` state into the consensus derivation pipeline.
- **Evidence Accountability:** Programmatically mandate that every verification submission include:
  1. An explicit categorical verdict selection (*TRUE*, *FALSE*, *MISLEADING*, or *UNVERIFIABLE*).
  2. A valid, fully qualified HTTP/HTTPS primary citation URL (e.g., government gazette, peer-reviewed medical study, established journalistic report, or judicial order).
  3. A concise, plain-language factual justification (between 50 and 500 characters) written in conversational terms suitable for public dissemination.

#### Objective 5: Multi-Factor Weighted Quorum Consensus Engine
- **Mathematical Scope:** Formulate and execute an algorithmic consensus scoring model that supersedes naive, easily manipulated 51% binary majority voting by synthesizing multi-party evidence into a bounded confidence percentage $C \in [0, 100]$:
  
  $$C = (A \times 40\%) + (R \times 30\%) + (S \times 30\%)$$
  
  Where:
  - **$A$ (Agreement Ratio):** The mathematical proportion of participating quorum verifiers voting in alignment with the majority verdict:
    
    $$A = \left( \frac{N_{\text{majority}}}{N_{\text{total}}} \right) \times 100$$
    
  - **$R$ (Verifier Reputation Index):** The normalized arithmetic mean of the historical reputation scores ($R_i \in [0, 100]$) of all verifiers participating in the quorum:
    
    $$R = \frac{1}{N} \sum_{i=1}^{N} R_i$$
    
  - **$S$ (Source Credibility Tier):** The normalized domain authority score assigned to the submitted reference URLs based on institutional verifiability:
    
    $$S = \frac{1}{N} \sum_{i=1}^{N} Q(\text{Domain}_i) \times 100$$
    
    Where $Q \in \{1.0 \text{ [Tier 1: Government/Academic/WHO]}, 0.70 \text{ [Tier 2: Mainstream Media]}, 0.30 \text{ [Tier 3: Unverified/Blogs]}\}$.
- **Classification State Machine:** Programmatically assign one of five deterministic claim states: *TRUE*, *FALSE*, *MISLEADING*, *UNVERIFIABLE*, or *CONTESTED* (when voting remains evenly split after 7 days).

#### Objective 6: Tamper-Resistant Verifier Reputation & Anti-Sybil Defense
- **Reputation Dynamics:** Construct an automated reputation ledger tracking individual verifier performance over time:
  - Baseline initialization at **$R_0 = 50$** upon account creation, bounded within the interval $[0, 100]$.
  - Algorithmic reward loop incrementing verifier score by **$+2$ points** when an assessment aligns with the final certified quorum consensus.
  - Penalization loop deducting **$-3$ points** for negligent, fraudulent, or malicious outlier votes that contradict validated consensus.
- **Anti-Sybil Cryptographic Locks:** Author declarative Cloud Firestore v12.17.0 database security rules that programmatically enforce:
  
  ```javascript
  // Declarative Anti-Self-Verification Lock in firestore.rules
  allow create: if request.auth != null 
                && request.auth.uid != get(/databases/$(database)/documents/claims/$(claimId)).data.submittedBy;
  ```
  
  This programmatic constraint prevents malicious actors from submitting fraudulent claims and immediately validating them using collusive auxiliary accounts (Sybil attack rings).

#### Objective 7: WhatsApp-Native Visual Artifact Generation (1080×1080px Fact Card)
- **Rasterization Architecture:** Design and deploy a client-side graphical compiler utilizing **`html-to-image` 1.11.13** that leverages modern browser-native SVG `<foreignObject>` canvas rasterization to transform rendered React DOM components into high-resolution, unalterable square PNG cards.
- **Color-Space Fidelity:** Guarantee complete native compatibility with **Tailwind CSS v4.0.0** OKLCH color spaces (`oklch()`, `oklab()`) and dynamic CSS custom properties without requiring brittle stylesheet patching or experiencing parsing crashes encountered in legacy canvas libraries.
- **Visual Design Specifications:** Render visual stamps incorporating unambiguous verdict color banners (Emerald Green for True, Crimson Red for False, Amber Orange for Misleading, Slate Gray for Unverifiable), claim summaries, dynamic SVG Trust Rings, source domain pills, and verification timestamps.

#### Objective 8: Public Misinformation Surveillance & Analytical Transparency
- **Real-Time Surveillance Dashboard:** Construct a comprehensive, responsive analytics dashboard powered by **Recharts 2.10.0** declarative SVG rendering, synchronizing live with Firestore collections.
- **Surveillance Metrics:** Aggregate 7-day rolling windows detailing total submission volume, category distributions (Health, Political, Financial, Religious), weekly rumor surges, consensus derive latency, and verifier leaderboard accuracy ratings.
