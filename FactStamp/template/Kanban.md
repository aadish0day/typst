# Kanban:
Kanban is an Agile project management method used to manage and improve the flow of work during software development.
The word "Kanban" is a Japanese term meaning "visual card" or "signboard."
It helps teams visualize tasks, limit work in progress (WIP), and deliver software continuously.
Unlike Scrum, Kanban does not require fixed-length sprints. Tasks are completed and delivered whenever they are ready.

# History of Kanban:
Origin at Toyota (1940s–1950s)
Kanban originated in Japan as a method to improve manufacturing efficiency.
It was later adapted for software development as part of Agile practices to manage work and improve productivity.
Kanban was developed by Taiichi Ohno, an industrial engineer at Toyota Motor Corporation.
In the late 1940s and early 1950s, Toyota wanted to improve its manufacturing process and reduce waste.
Taiichi Ohno observed how supermarkets restocked shelves only when customers purchased items.
This inspired the "pull system", where production starts only when there is demand.
He introduced Kanban cards to signal when parts needed to be produced or replenished.

# History of Kanban:
Kanban in Software Development (2004–2007)
Around 2004–2007, David J. Anderson adapted Kanban principles for software development.
He introduced the Kanban Method, applying visual workflow management and work-in-progress (WIP) limits to software teams.
 The method allowed teams to improve processes without making major organizational changes.

# Principles of Kanban:
1. Visualize the Workflow
All tasks are displayed on a Kanban board so everyone can see the project's progress.
2. Limit Work in Progress (WIP)
Only a limited number of tasks can be in the "In Progress" column at a time.
Example: Maximum 3 tasks can be in progress simultaneously.
3. Manage Flow
The goal is to keep work moving smoothly from "To Do" to "Done."
4. Continuous Improvement
Teams regularly identify problems and improve the process.
5. Pull System
Team members pull new work only after completing their current task instead of being assigned many tasks at once.

<!-- Slide number: 8 -->
| Current Issue | How Kanban Helps |
| --- | --- |
| Burnout | Kanban limits the amount of work each team member can handle at a time (WIP limits). This prevents overloading developers and reduces stress. |
| Frequent bugs in production | Teams focus on completing fewer tasks at a time, allowing better testing, code reviews, and higher-quality software before release. |
| Complaints about productivity | Kanban makes work visible on a board (To Do → In Progress → Testing → Done), making it easier to track progress and identify delays. |
| Low throughput | By removing bottlenecks and reducing multitasking, work flows faster, increasing the number of completed tasks over time. |
| Vague sprint planning | Kanban doesn’t rely on fixed sprints. Work is pulled based on priority and team capacity, reducing the need for complex sprint planning. |
| Too much work in one sprint | Since Kanban uses continuous flow instead of fixed sprint commitments, teams only take new work when they have capacity. |
| Unidentified bottlenecks | The Kanban board clearly shows where tasks are getting stuck (e.g., Testing or Code Review), allowing the team to fix process issues quickly. |
