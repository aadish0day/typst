# 2.3 Styling Architectures, Design Systems & Pan-Indic Typography

## 2.3.1 Introduction and Design Challenges
In digital misinformation defense, visual ergonomics and typographic clarity are not superficial aesthetic enhancements—they are mission-critical socio-technical requirements. WhatsApp users encounter misinformation across diverse, high-stress physical environments: bright outdoor tropical sunlight, low-cost TN/IPS mobile screens with poor viewing angles, and variable display resolutions ranging from $360 \times 640$px smartphones to high-DPI desktop monitors.

Furthermore, a counter-disinformation artifact (such as FactStamp's exportable square Fact Card) must command instant institutional credibility. If a debunking card looks amateurish, unpolished, or illegible, WhatsApp chat group participants intuitively dismiss it as another piece of partisan spam.

To establish this visual authority, the styling infrastructure must satisfy four core architectural criteria:
1. **Zero Runtime Overhead:** Style evaluation must not block the main JavaScript thread on budget mobile hardware.
2. **Native Wide-Gamut Color Uniformity:** Color tokens must maintain perceptual contrast consistency across varying device displays using modern color science (OKLCH color space).
3. **Pan-Indic Vernacular Typography:** Native glyph rendering for Indian languages (specifically Hindi and Marathi via Devanagari script) with zero broken ligatures or font baseline shifts.
4. **Accessible Contrast Compliance:** Text and verdict badges must pass stringent Accessible Perceptual Contrast Algorithm (APCA) contrast standards ($L_c > 75$).

Four styling methodologies were evaluated: **Tailwind CSS v4.0.0 (Oxide)**, **Bootstrap 5**, **CSS Modules**, and **Styled-Components (CSS-in-JS)**.

## 2.3.3 The Saffron Sleek Design System

FactStamp establishes a unique visual identity—**Saffron Sleek**—engineered specifically for high-contrast mobile legibility in Indian social environments.

```text
+--------------------------------------------------------------------------------------------------+
|                                  SAFFRON SLEEK DESIGN SYSTEM TOKENS                              |
+----------------------+-----------------------------+---------------------------------------------+
| Token Category       | Light Mode Value            | Dark Mode Value                             |
+----------------------+-----------------------------+---------------------------------------------+
| Canvas / Surface     | #FFFDF8                     | oklch(0.115 0.018 55)                       |
|                      | (Warm, low-strain cream)    | (Deep warm charcoal)                        |
+----------------------+-----------------------------+---------------------------------------------+
| Primary Accent       | #BA3E03                     | #D97706                                     |
| (Brand Saffron)      | oklch(0.50 0.18 48)         | oklch(0.65 0.18 65)                         |
+----------------------+-----------------------------+---------------------------------------------+
| Text Primary         | #1C1917 (Stone-900)         | #F5F5F4 (Stone-100)                         |

+----------------------+-----------------------------+---------------------------------------------+
| Card Container       | #FFFFFF                     | oklch(0.165 0.022 55)                       |
| Border Stroke        | 1px solid #E7E5E4           | 1px solid oklch(0.24 0.025 55)              |
+----------------------+-----------------------------+---------------------------------------------+
```

### 1. The Science of OKLCH Color Geometry
Traditional sRGB and HSL color models suffer from severe perceptual non-uniformity: two colors with identical saturation and lightness values (e.g., pure yellow vs. pure blue) exhibit drastically different perceived brightness to the human visual cortex. In contrast, the **OKLCH** color space (Lightness, Chroma, Hue) is mathematically calibrated to human perceptual vision:
- $L$ represents Perceived Lightness ($0.0$ to $1.0$).
- $C$ represents Chroma / Color Purity ($0.0$ to $\approx 0.4$).
- $H$ represents Hue Angle ($0^\circ$ to $360^\circ$).

By declaring design tokens in OKLCH, FactStamp guarantees that UI elements share consistent perceived luminance across transitions between light mode and dark mode, preventing visual glare or illegible contrast drops.

### 2. Semantic Verdict Gamut
The verification engine categorizes claims into four distinct verdicts, each mapped to a mathematically calibrated OKLCH token:
- **TRUE:** Vivid emerald green (`#059669` / `oklch(0.62 0.17 155)`). Inspires trust and safety without blinding glare.
- **FALSE:** High-urgency crimson red (`#DC2626` / `oklch(0.57 0.22 27)`). Commands immediate attention and communicates a definitive hazard signal.
- **MISLEADING:** Cautious amber orange (`#D97706` / `oklch(0.65 0.18 65)`). Indicates context distortion, cherry-picked data, or altered media.
- **UNVERIFIABLE:** Neutral slate gray (`#475569` / `oklch(0.48 0.04 250)`). Denotes inconclusive evidence, expired sources, or unverifiable claims.

### 3. Universal Theme Toggle (`<ThemeToggle />`)
The application implements an accessible sliding dual-icon theme toggle component. The toggle smoothly transitions the root document class between `.light` and `.dark`, synchronizing preference to `localStorage` and respecting the operating system's `prefers-color-scheme` media query.

## 2.3.4 Pan-Indic Typography & Tabular Numerics

Misinformation in India is predominantly multilingual. Hindi and regional vernacular forwards circulate widely alongside English text. The typographic hierarchy is engineered to render mixed-script WhatsApp forwards with zero visual clipping or missing font glyphs:

```text
Typographic Stack Hierarchy
├── Primary Newsroom Sans: "Plus Jakarta Sans" (Variable 400–800)
│   └── Crisp, authoritative editorial geometry for English headlines & UI controls.
│
├── Native Vernacular Devanagari: "Noto Sans Devanagari" (400, 500, 600, 700)
│   └── Complete Unicode Devanagari ligature support for Hindi & Marathi forwards.
│
└── Zero-Payload Fixed-Width Numerics: CSS "font-variant-numeric: tabular-nums"
    └── Aligns quorum ratios (0/3), confidence % (93.1%), and timers with 0 KB font overhead.
```

### 1. Eliminating Glyph Collapse via Noto Sans Devanagari
When standard Western fonts encounter Devanagari characters (e.g., Hindi: "भारतीय रिजर्व बैंक"), the browser falls back to disparate system fonts, resulting in irregular baseline jumps, misaligned vowel matras (मात्रा), and clipped top headline bars (शिरोरेखा). FactStamp explicitly bundles and prioritizes *Noto Sans Devanagari*, guaranteeing consistent vertical metrics and baseline harmony across mixed English-Hindi text.

### 2. Zero-Cost Monospace Metrics via `tabular-nums`
In collaborative verification dashboards, live numbers (e.g., countdown timers, quorum counters $1/3 \rightarrow 2/3$, confidence ratings $93.1\%$) frequently update. Standard proportional fonts cause the surrounding text to jitter and shift horizontally because the digit "1" is narrower than the digit "8".

Rather than downloading an external monospace coding font (which would add 40–70 KB of network payload), FactStamp leverages native CSS OpenType font features:
```css
.tabular-metrics {
  font-variant-numeric: tabular-nums;
  letter-spacing: -0.02em;
}
```
This forces all digits ($0$ through $9$) to share identical horizontal glyph bounding boxes, delivering jitter-free alignment with zero additional HTTP font download penalty.

## 2.3.5 Architectural Decision Record (ADR)

* **Title:** ADR-03: Selection of Tailwind CSS v4.0.0 and Saffron Sleek OKLCH Design Tokens
* **Status:** Accepted and Fully Implemented.
* **Context:** FactStamp requires a styling system delivering zero JavaScript runtime overhead, consistent wide-gamut contrast across diverse mobile displays, and native support for vernacular Indian typography.
* **Decision:** Adopt Tailwind CSS v4.0.0 powered by the Rust-based Oxide engine. Implement the Saffron Sleek design system using OKLCH color spaces, paired with Plus Jakarta Sans and Noto Sans Devanagari fonts.
* **Consequences:** Eliminates style-injection render stalls on budget mobile hardware; guarantees APCA $L_c > 75$ contrast compliance across all lighting conditions; delivers flawless rendering for multilingual WhatsApp forwards.
