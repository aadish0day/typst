# 6.2 User Documentation and Operational Manuals

---

## 6.2.1 Introduction and System Personas

**FactStamp** is architected to operate with minimal friction across heterogeneous user groups within the Indian digital communications landscape. To provide intuitive guidance suited to different levels of technical literacy, the platform delineates three primary operational personas:

1. **The Submitter (Everyday WhatsApp User):** Individuals who receive suspicious, viral forwards in family, neighborhood, or professional WhatsApp groups and seek instant veracity checks without undergoing complex registration or authentication barriers.
2. **The Verifier (Community Researcher / Student Fact-Checker):** Authenticated community members who utilize the verification queue workbench to investigate unverified claims, cross-reference credible primary and secondary evidence, submit structured verdicts, and build community reputation.
3. **The Administrator (System Moderator / Faculty Supervisor):** Authorized operators responsible for platform health oversight, expedited review escalation, dispute resolution for contested claims, and anti-abuse enforcement.

The subsequent sections present comprehensive, step-by-step operational manuals for each persona, including user interface navigation, action sequences, validation constraints, and visual feedback states.

## 6.2.2 Submitter User Guide

The Submitter workflow is engineered for frictionless, rapid engagement, enabling users to transition from receiving a forwarded rumor to possessing a verified counter-artifact within seconds.

```
WhatsApp Forward Received ──> Open FactStamp Web App ──> Submit Text or Screenshot
                                                               │
                       ┌───────────────────────────────────────┴───────────────────────────────────────┐
                       ▼                                                                               ▼
             Text Normalization                                                              OCR Text Extraction
                       │                                                                               │
                       └───────────────────────► Jaccard Duplicate Engine ◄───────────────────────────┘
                                                           │
                                ┌──────────────────────────┴──────────────────────────┐
                                ▼                                                     ▼
                     Duplicate Match (J >= 0.75)                            Unique Claim (J < 0.75)
                                │                                                     │
                     Instant Redirect to Result                            Enters Verification Queue
                                │                                                     │
                     Download Fact-Check Card                                3 Community Reviews
                                │                                                     │
                     Re-Forward to WhatsApp                                Final Verdict & Card Ready
```

### 1. Accessing the Application
- **URL & Browser Compatibility:** Launch any modern web browser (Google Chrome, Mozilla Firefox, Apple Safari, Microsoft Edge, or Samsung Internet) on mobile, tablet, or desktop and navigate to the application endpoint (`https://factstamp.vercel.app` or local development instance).
- **Authentication Status:** Claim submission does *not* require account creation or login. Unauthenticated visitors can immediately submit forwards and download fact-check cards.

### 2. Submitting a Text-Based Forward
1. **Navigate to Submit:** Click or tap the **"Submit a Forward"** button on the home screen hero banner or the **"Submit"** item in the main navigation bar.
2. **Select Submission Mode:** Ensure the **"Paste Text"** tab is highlighted.
3. **Enter Forward Text:** Paste the exact forward text received in WhatsApp into the multiline input field.
   - *Minimum Length:* Claims must contain at least 20 characters to provide meaningful linguistic context.
   - *Maximum Length:* Inputs up to 3,000 characters are supported without truncation.
4. **Select Category (Optional):** Categorize the claim using the dropdown selector:
   - `Health` (remedies, medical panaceas, disease rumors)
   - `Political` (politician statements, policies, elections)
   - `Financial` (recharge schemes, subsidies, banking alerts)
   - `Religious` (cultural celebrations, historical claims)
   - `Other` (general viral hoaxes)
5. **Click "Verify Forward":** The button triggers client-side text sanitization (`sanitizeTextInput`) and executes the Jaccard duplicate query.

### 3. Submitting an Image Screenshot Forward
1. **Switch to Screenshot Mode:** Click or tap the **"Upload Screenshot"** tab.
2. **Select Image File:** Tap the upload dropzone or drag and drop a screenshot file (`.jpg`, `.jpeg`, `.png`, `.webp`).
   - *File Size Limit:* Maximum 5.0 MB per image.
   - *Triple-Layer Security Defense:* The file undergoes extension whitelisting, MIME type validation, and binary magic byte header inspection (`0xFF 0xD8 0xFF` for JPEG, `0x89 0x50 0x4E 0x47` for PNG) to abort polyglots and malicious scripts.
3. **Automatic Client-Side Compression & OCR:**
   - The client-side HTML5 Canvas downscales the image to $\le 1280\text{px}$ and iteratively steps JPEG quality down ($0.72 \to 0.40$) until the Base64 data URL fits within a strict $700\text{ KB}$ ceiling.
   - The in-browser Tesseract.js WASM engine automatically parses text from the chat bubble or status card.
4. **Review and Edit Extracted Text:** The OCR-extracted text is populated in an editable preview textarea. If the screenshot suffered from low resolution or stylized fonts, the submitter can manually correct misspelled words or names before final submission.
5. **Submit for Processing:** Tap **"Submit Claim"** to begin verification.

### 4. Interpreting the Result: Duplicate vs. New Queue
- **Instant Duplicate Match ($J \ge 0.75$):**
  - If the forward has previously undergone verification, FactStamp immediately displays an alert toast:  
    *"Duplicate Claim Detected: This viral forward has already been reviewed by our community!"*
  - The submitter is redirected immediately to the existing certified claim view without waiting.
- **New Claim Initialized ($J < 0.75$):**
  - If the claim is novel, it is assigned a unique Firestore document ID, given an initial status of `pending`, and placed in the community verification queue.
  - A persistent status toast displays: *"Claim successfully submitted to the Community Verification Queue. You will receive an alert once 3 independent verifiers reach consensus."*

### 5. Reading Verdict Badges and Confidence Stamps
Each completed fact-check presents a high-visibility, double-encoded **Verdict Stamp**:

| Verdict Stamp | Badge Color | Iconography | Meaning and Interpretation |
| :---: | :---: | :---: | :--- |
| **TRUE** | Emerald Green | Checkmark Icon | The claim is accurate and corroborated by authoritative primary documentation (e.g., official government gazettes, WHO bulletins). |
| **FALSE** | Crimson Red | Octagonal Cross Icon | The claim is demonstrably fabricated, doctored, fraudulent, or dangerous. Do not forward. |
| **MISLEADING** | Amber Orange | Warning Triangle Icon | The claim contains an element of truth that has been stripped of context, exaggerated, or manipulated. |
| **UNVERIFIABLE** | Slate Gray | Question Mark Icon | Insufficient credible evidence exists across public archives and primary sources to prove or disprove the claim. |
| **CONTESTED** | Violet Purple | Scale / Gavel Icon | Community verifiers submitted conflicting verdicts and could not achieve consensus within the 7-day deliberation window. |

Accompanying the stamp is the **Confidence Ring** (`TrustRing`), which displays the weighted algorithmic score ($C \in [0, 100]\%$) derived from verifier agreement ($40\%$), average verifier reputation ($30\%$), and source quality ($30\%$).

### 6. Downloading and Forwarding the Fact-Check PNG Card
1. On the verified claim page, tap the **"Download WhatsApp Card"** button.
2. The client-side `html-to-image` rasterizer compiles the live DOM template into a crisp, high-resolution $1080 \times 1080\text{px}$ square PNG image in $< 650\text{ ms}$.
3. The image file automatically downloads with a formatted filename (e.g., `factstamp-FS-202608-0104.png`).
4. **Forwarding Back to WhatsApp:**
   - Open WhatsApp on mobile or WhatsApp Web.
   - Navigate to the chat group where the fake forward originally appeared.
   - Attach and send the downloaded PNG card as an image.
   - Because the card contains the original claim quote, large color-coded stamp, confidence score, and verified URLs, it visually shuts down further viral re-sharing.

## 6.2.3 Verifier User Guide

Community verifiers are the investigative backbone of FactStamp. Verifiers must authenticate to build a persistent reputation score and ensure accountability.

### 1. Onboarding and Verifier Profile Setup
1. **Registration:** Click **"Sign In"** on the navigation bar. Choose between **"Sign in with Google"** (one-tap OAuth 2.0) or register via email and password.
2. **Baseline Reputation Score:** Every newly registered verifier is initialized with a neutral reputation score of **50 points** (scale 0–100) and zero recorded verifications.
3. **Trust Ring Profile Avatar:** Verifier avatars display an interactive SVG `TrustRing` colored according to reputation:
   - Green / Emerald Ring: High Reputation ($80–100$)
   - Blue / Saffron Ring: Good Reputation ($60–79$)
   - Amber Ring: Neutral Baseline ($40–59$)
   - Red Ring: Probationary ($< 40$)

### 2. Navigating the Verification Queue (`/verify`)
- The **Verification Queue** lists all claims with status `pending` awaiting quorum completion.
- **Queue Filtering Options:**
  - *By Category:* Filter by Health, Political, Financial, Religious, or Other.
  - *By Urgency:* Sort by newest submissions or claims closest to achieving quorum ($2/3$ verifications complete). Claims within 8 hours of the 7-day expiry display an amber pulsing urgency badge.
  - *By Expedited Flag:* Filter for claims highlighted by administrators for priority community review.
- **Anti-Self-Verification Lock:** A verifier cannot review a claim they originally submitted. If a user attempts to verify their own claim, the action button is disabled with the notice: *"You cannot verify your own submission (Anti-Sybil Rule)."*

### 3. Conducting Structured Claim Investigation
When clicking on a claim card in the queue, the verifier enters the **Workbench View** (`/verify/:id`):
1. **Inspect Claim Content:** Read the normalized claim text, review the original uploaded screenshot, and inspect submission timestamp and category.
2. **Search Authoritative Sources:** Cross-reference the claim across reputable search engines, government archives, scientific journals, or official press releases.
3. **Source Quality Evaluation Matrix:** When inputting evidence URLs, the system categorizes domains into three quality tiers:

| Source Quality Tier | Permitted Domains & Evidence Types | Algorithmic Weight ($S_i$) |
| :---: | :--- | :---: |
| **High Quality (Tier 1)** | Government portals (`.gov.in`, `.nic.in`), World Health Organization (`who.int`), ICMR, Ministry of Health (`mohfw.gov.in`), Press Information Bureau (`pib.gov.in`), Election Commission (`eci.gov.in`), Supreme Court / Indian Code. | **100 points** ($1.0$) |
| **Medium Quality (Tier 2)** | Established wire services (Reuters, AP News), accredited national news dailies (The Hindu, Indian Express, Times of India, NDTV, BBC), verified IFCN fact-checkers (AltNews, BOOM Live, FactCheck.org, Snopes). | **70 points** ($0.70$) |
| **Low Quality (Tier 3)** | Personal blogs, unverified digital forums, social media posts, secondary commentary lacking citations. | **30 points** ($0.30$) |

### 4. Submitting a Verdict
1. **Choose Verdict:** Select one of the candidate verdicts (`TRUE`, `FALSE`, `MISLEADING`, `UNVERIFIABLE`).
2. **Provide Canonical Source URL:** Enter a valid HTTP/HTTPS URL pointing directly to the fact-checking article, government circular, or scientific report. The system validates URL syntax in real time.
3. **Write Plain-Language Explanation:** Write a concise rationale explaining why the cited source confirms or refutes the claim.
   - *Validation Rules (`src/lib/security.ts`):*
     - Minimum 50 characters, maximum 1,500 characters.
     - Minimum 8 distinct words.
     - Rejection of repetitive character spam (e.g., `aaaaaa`) and generic cop-out filler (`"trust me bro"`, `"google it"`).
     - Interactive animated word-count progress bar guides the user to threshold completion.
4. **Submit Verdict:** Click **"Submit Verification"**. The submission is committed as an atomic sub-document inside Firestore.

### 5. Quorum Execution and Reputation Dynamics
- **Quorum Requirement ($N \ge 3$):** A claim remains in the queue until three independent verifiers submit reviews.
- **Consensus Derivation:** Once the third review is recorded, the Consensus Engine runs automatically:
  $$C = \text{round}((A \times 40\%) + (R \times 30\%) + (S \times 30\%))$$
- **Reputation Adjustments:**
  - *Consensus Alignment:* Verifiers whose votes matched the majority verdict receive $+2$ reputation points.
  - *Outlier / Contradictory Vote:* Verifiers who voted against the majority receive a $-1$ point deduction.
  - *Malicious / Bad-Faith Submissions:* Verifiers caught submitting spoofed URLs or spam are penalized $-15$ points and flagged for administrative review.

## 6.2.4 Administrator Guide

Administrators maintain platform integrity, govern disputed consensus outcomes, and supervise community health.

### 1. Accessing the Admin Console (`/admin`)
- Administrative features are protected by role-based access control (RBAC) enforced in both client-side route guards (`src/components/AdminRoute.tsx`) and Firestore Security Rules (`request.auth.token.isAdmin == true`).
- Upon logging in with an administrator account, the navigation header displays the **"Admin Console"** tab.

### 2. Monitoring Real-Time Analytics and System Health
The Admin Dashboard presents key operational gauges:
- **Active Verification Backlog:** Real-time count of pending claims sorted by queue residence time.
- **Daily Ingestion Rate:** Total forward submissions per 24-hour cycle categorized by text vs. screenshot OCR.
- **Consensus Turnaround Time:** Average duration from submission to certified consensus publication (averaging 18.4 hours during active trials).
- **Weekly Misinformation Breakdown:** Recharts graphical visualization of circulating rumor categories.

### 3. Handling Contested Claims and Timeouts
- **7-Day Timeout Policy:** Claims that fail to achieve a decisive majority within 7 days or remain locked in a split decision automatically transition to status `CONTESTED`.
- **Administrative Action Workflow:**
  1. Open the **"Contested Claims"** tab in the Admin Console.
  2. Inspect the conflicting verifications and cited URLs.
  3. The administrator may:
     - **Extend Deliberation Window:** Re-queue the claim with an "Expedited Review" badge to solicit additional verifier votes ($N = 5$ expanded quorum).
     - **Issue Administrative Certification:** In cases of severe public health danger (e.g., toxic chemical remedies), certify the verdict directly with institutional citations.
     - **Dismiss as Ambiguous:** Permanently certify the claim as `UNVERIFIABLE`.

### 4. Moderation, Sybil Defense, and User Management
- **Audit Verifier Profiles:** View the verifier registry sorted by total verifications, accuracy ratio, and reputation trajectory.
- **Account Sanctions:**
  - *Warning Issue:* Send an in-app administrative notification regarding low-effort rationale text.
  - *Reputation Reset:* Reset a suspicious account's reputation to zero, neutralizing their influence in the consensus formula.
  - *Permanent Ban:* Revoke verification privileges for coordinated Sybil accounts or persistent trolls.
- **Audit Logs:** Review Firestore security rule violations, rate-limited login attempt spikes, and rejected image upload logs.

## 6.2.6 Comprehensive System Message and Recovery Matrix

| System Message / Alert | Trigger Condition | System Behavior & Root Cause | User Recovery Action |
| :--- | :--- | :--- | :--- |
| **"Duplicate Claim Detected"** | Incoming text matches existing record ($J \ge 0.75$). | Prevents redundant queues; redirects client to certified dossier. | No action needed. View verified card and share back to WhatsApp. |
| **"File exceeds limit (5.0 MB)"** | Uploaded screenshot $> 5.0\text{ MB}$. | Client-side file guard blocks memory exhaustion. | Crop screenshot or save in standard JPEG/PNG before uploading. |
| **"File content invalid"** | Magic byte header mismatch detected. | Disguised executable or corrupted media detected. | Upload an authentic screenshot captured on mobile device. |
| **"Explanation too short"** | Rationale $< 50$ chars or $< 8$ words. | Enforces analytical rigor; blocks low-effort cop-out votes. | Expand rationale explaining why cited link disproves claim. |
| **"Self-verification blocked"** | User attempts to verify own claim. | Anti-Sybil security rule prevents collusion. | Browse other pending claims in queue submitted by peers. |
| **"Account locked (15 min)"** | 5 failed password attempts. | Brute-force throttle prevents credential stuffing. | Wait 15 minutes or reset password via registered email. |
| **"Network disconnected"** | Device lost internet connectivity. | Persistent warning; offline cache saves local inputs. | Check Wi-Fi/4G. Mutations will replay upon reconnection. |

## 6.2.7 Frequently Asked Questions (FAQs)

1. **Does FactStamp monitor private WhatsApp chats?**  
   *Answer:* No. The platform operates strictly on user-initiated submissions; it has zero access to WhatsApp encryption keys or chat databases.
2. **Why 3 verifiers instead of generative AI?**  
   *Answer:* LLMs are prone to factual hallucinations and lack awareness of hyper-local Indian events. Human consensus backed by verifiable primary citations ensures legal accountability.
3. **Can a coordinated bot brigade certify a lie?**  
   *Answer:* No. FactStamp's weighted algorithm factors historical reputation ($30\%$) and source authority ($30\%$). Low-credibility accounts citing unverified blogs cannot override high-reputation verifiers citing official gazettes.
4. **How to share back to WhatsApp?**  
   *Answer:* Click *"Download WhatsApp Card"*, save the 1080x1080px image, and attach it directly to the group chat where the rumor appeared.
