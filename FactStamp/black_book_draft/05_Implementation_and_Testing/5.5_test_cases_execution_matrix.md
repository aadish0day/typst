# 5.5 Test Cases (Execution Matrix)

The table below is the **executed** counterpart to Chapter 4.6's test case design — each row was actually run manually (per the approach in §5.3) against a running instance of FactStamp on the Firebase Local Emulator Suite, and the Actual Result / Pass column reflects the real outcome observed, not a projected one. Only one row is marked as a historical failure, corresponding to the verification-queue auto-replenishment defect documented and fixed in §5.4 — every other scenario passed on the build current at the time of this dissertation.

| Test ID | Test Condition | Input | Expected Result | Actual Result | Pass/Fail |
|---|---|---|---|---|---|
| TC-01 | New user registration | Valid email + password via `SignUp.tsx` | Firebase Auth account created; `users/{uid}` Firestore profile created with base `reputation: 50` | Account and profile created as expected; user auto-signed-in | Pass |
| TC-02 | Duplicate email registration | Email already registered | Registration rejected with a clear "email already in use" error | Rejected with expected error, no duplicate profile created | Pass |
| TC-03 | Login lockout after repeated failures | 5 consecutive wrong-password attempts, then a 6th | Account locked for 15 minutes after the 5th attempt; 6th attempt blocked before hitting Firebase Auth | Locked exactly at attempt 5; countdown banner shown; 6th attempt blocked client-side | Pass |
| TC-04 | Text claim submission | Plain-text WhatsApp forward pasted into `Submit.tsx` | Claim created with `status: pending`, normalized text stored, added to Verification Queue | Claim created and visible in queue within one Firestore write | Pass |
| TC-05 | Screenshot claim submission with OCR | WhatsApp forward screenshot (JPEG) uploaded | Image compressed client-side; Tesseract.js extracts readable text; WhatsApp chrome (timestamp/checkmarks) stripped by `cleanExtractedOcrText()` | Text extracted and chrome removed; user shown extracted text for confirmation before submit | Pass |
| TC-06 | Duplicate detection — identical claim | Claim text identical to an existing resolved claim | $J(A,B) = 1.00 \ge 0.75$; user redirected to existing claim page | Redirected correctly; no new claim created | Pass |
| TC-07 | Duplicate detection — near-paraphrase | Claim text differing by one word from an existing claim (see §5.3.1 Case 2, $J = 0.80$) | Flagged as duplicate; redirected | Redirected correctly | Pass |
| TC-08 | Duplicate detection — related but distinct claim | Claim text topically similar but below threshold (see §5.3.1 Case 3, $J = 0.56$) | *Not* flagged; new claim created independently | New claim correctly created, not merged | Pass |
| TC-09 | Verifier explanation — too short | Verdict submitted with a 4-character explanation ("fake") | Rejected client-side with a specific "explanation too short" error before any Firestore write | Rejected with expected error message | Pass |
| TC-10 | Verifier explanation — valid | Verdict submitted with a properly-sourced, 50+ character explanation and a real citation URL | Accepted; verification appended to claim's embedded array; `verificationCount` incremented by exactly 1 | Accepted and appended correctly | Pass |
| TC-11 | Self-verification block | User attempts to verify a claim they themselves submitted | Submission blocked client-side with an anti-Sybil warning | Blocked as expected before reaching Firestore | Pass |
| TC-12 | 3-verifier quorum consensus | Three distinct verifiers each submit a verdict on the same claim | On the 3rd verification, `calculateConfidenceScore()` runs; claim `status` transitions `pending` → `verified`; confidence score matches hand-computed value | Transition occurred on 3rd verification; computed score matched manual calculation exactly | Pass |
| TC-13 | Consensus expiry to CONTESTED | Claim's `consensusDeadline` passes with fewer than 3 verifications | Claim auto-settles as `verdict: CONTESTED` via `applyLocalExpiry()`, using whatever partial verification data exists for the confidence score | Claim correctly settled as CONTESTED at deadline | Pass |

| TC-15 | Fact-check PNG card export | Export a resolved claim's card via `html-to-image` | PNG downloaded at 1080px width (540px card rasterized at `pixelRatio: 2`), height scaling to fit the card's content; OKLCH-based theme colors render correctly, no black/broken regions | Exported at 1080px width with correct colors; height varied with claim-text and source-list length, as the unconstrained card layout implies | Pass |
