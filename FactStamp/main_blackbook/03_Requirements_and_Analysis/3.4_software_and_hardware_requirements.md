## 3.4.1 Software Requirements

### A. Development & Build Environment

| Component | Requirement / Version | Purpose |
|---|---|---|
| Operating System (dev machine) | Linux (Arch/Ubuntu), macOS 13+, or Windows 10/11 with WSL2 | Cross-platform development; CI runs on Linux runners |
| Node.js | v20.x LTS or v22.x LTS | JavaScript runtime for Vite build tooling and npm scripts |
| Package Manager | npm (bundled with Node.js) | Dependency installation and script execution |
| Git | 2.40+ | Version control |
| Firebase CLI | Latest (`firebase-tools`) | Local Emulator Suite (Auth :9099, Firestore :8080, Storage :9199), deployment to Firebase Hosting |
| Visual Studio Code | Latest | Primary IDE (TypeScript/ESLint/Tailwind IntelliSense extensions) |
| Docker & Docker Compose | Latest stable | Optional containerized production build (multi-stage Node → Nginx image) |
| Typst | v0.15.1 | Dissertation/black-book document typesetting (this workspace) |
| PlantUML | Latest (requires JVM / OpenJDK 21) | UML diagram source compilation for Chapter 3.6 and Chapter 4 diagrams |
| Graphviz | Latest (`dot` binary) | DFD diagram compilation for Chapter 3.6 |

### B. Core Application Dependencies (Runtime, bundled into the client build)

| Package | Version | Role |

### C. End-User (Client) Software Requirements

| Component | Minimum Requirement |
|---|---|
| Web Browser | Google Chrome 111+, Mozilla Firefox 113+, Apple Safari 15.4+, or Microsoft Edge 111+ (these are the first versions supporting the CSS `oklch()`/`oklab()` color functions the design system requires, alongside WebAssembly and ES2022) |
| Operating System | Any OS with a supported modern browser (Windows 10+, macOS 12+, Android 10+, iOS 15+, current Linux distributions) |
| JavaScript | Must be enabled (the application is a JavaScript Single Page Application; it does not function without it) |

## 3.4.2 Hardware Requirements

Because FactStamp is a purely client-side web application with a serverless (Firebase-managed) backend, this project specifies no dedicated application-server hardware. The relevant hardware requirements are the client device's minimums for running the browser, the OCR WebAssembly module, and the card-rasterization pipeline smoothly.

### A. Client (End-User) Device — Minimum Requirements

| Resource | Minimum | Recommended |
|---|---|---|
| Processor | Dual-core 1.8 GHz 64-bit CPU (ARM or x86_64) | Quad-core 2.0 GHz+ |
| RAM | 2 GB | 4 GB (recommended specifically for in-browser Tesseract.js OCR processing, which is memory-intensive during WASM initialization) |
| Display Resolution | 360×640 (entry-level mobile) | 1920×1080 (desktop Full HD) or higher |
| Storage | Negligible (no local install; browser cache only, typically < 50 MB after Tesseract WASM model caching) | — |
| Network | 3G / stable low-bandwidth connection sufficient for text and card operations | 4G / broadband for faster initial screenshot upload and OCR model download |
| Camera / File Picker | Required only if submitting a screenshot claim (not required for text-only claims) | — |

### B. Development Machine — Minimum Requirements

| Resource | Minimum | Recommended |
|---|---|---|
| Processor | Dual-core 2.0 GHz | Quad-core 2.5 GHz+ (faster Vite HMR and Docker builds) |
| RAM | 8 GB | 16 GB (comfortable headroom for VS Code + Chrome DevTools + Firebase Emulator Suite + Docker simultaneously) |
| Storage | 10 GB free (node_modules, Docker images, Firebase Emulator data) | 20 GB+ SSD |
| Network | Broadband internet (Firebase Console access, npm registry, GitHub) | — |

### C. Backend / Cloud Infrastructure (Managed, Not Self-Provisioned)

| Layer | Provider | Notes |
|---|---|---|
| Authentication | Firebase Authentication | Fully managed; no server hardware provisioned by this project |
| Database | Google Cloud Firestore (multi-region NoSQL) | Fully managed, Spark (free) tier: 50,000 document reads and 20,000 document writes per day, with 1 GiB of total stored data |
| Static Hosting | Firebase Hosting / Vercel Edge Network / self-hosted Docker + Nginx | Firebase Hosting and Vercel are fully managed CDN-backed; the Docker option is the only self-hosted target and can run on any machine meeting the development-machine minimums above |
| CI | GitHub Actions (hosted runners) | Runs TypeScript typecheck, production build, and `docker-compose config` validation on every push — no self-hosted CI runner required |
